WHAT CHANGED
--------------------------------------------------------------------
Added, right in <head>, alongside the existing viewport/theme-color
meta tags:

    <meta name="referrer" content="strict-origin-when-cross-origin">

Worth being precise about the syntax: the standard way to deliver this
is a <meta name="referrer"> tag — not an http-equiv="Referrer-Policy"
variant, which isn't how this one is actually specified (easy mix-up
by analogy with how the CSP meta tag right below it uses http-equiv,
but Referrer Policy's HTML integration is specifically name="referrer").

Chose "strict-origin-when-cross-origin" specifically: it's what every
current browser already defaults to, so this changes nothing about
actual behavior today — it makes the policy explicit and intentional
rather than relying on an implicit default, as a safety net for any
older or unusual browser that might still default to something looser.
It also stays compatible with Google Sign-In (loaded further down):
that still needs the request's origin on cross-origin navigation,
which this policy still sends — a stricter "no-referrer" would strip
that too and risked interfering with that flow, so that option was
deliberately not used here.

Honest framing, not oversold: this app's own pages don't currently put
anything sensitive in a URL (no tokens or amounts in query strings),
so there's no active leak being closed today. This is about not
depending on that staying true forever, on either the browser-default
side or this app's own URL usage down the line, for close to zero cost
to add now.
